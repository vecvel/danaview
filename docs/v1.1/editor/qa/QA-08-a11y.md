# QA-08 · Accessibility pass (guidelines, VoiceOver, TalkBack)

Owner ticket: QA-08 (BUILD_PLAN §6, M6). Spec: ARCHITECTURE §17.9, §1.3 rules 4 and 6; ux.md §19.1.
Run date of this record: 2026-10-15 (Mac lane, branch `editor-wip`, Flutter 3.44).

## 1. How to run

```sh
cd packages/danaview_editor && flutter test test/a11y
```

One command and no device needed. It runs 222 widget and unit tests in about 25 s on the dev Mac. A single
surface or flow reproduces with `--plain-name`, for example
`flutter test test/a11y/panels_a11y_test.dart --plain-name "[280x500 @1.35 android] SpeedInspector"`.

### 2.1 Exemptions (documented, deliberate)

1. **Timeline content size.** Clip, caption, text, marker, keyframe and transition nodes are painted at the size of their time range and lane. ARCH §17.2 sets text and subtitle lanes at 32 px or more and the ruler at 24 px. Each of these nodes has non-spatial equivalents: custom actions, the context tool strip and the keyboard shortcuts. That is WCAG 2.5.8's "equivalent" exception. The suite does not check their size. It checks their labels and, for clips, the full edit action set.
2. **Disabled tool tiles.** By design (ux.md §9.2) these stay tappable at 40% opacity so a tap can explain why they are disabled. WCAG 1.4.3 exempts inactive components. Flutter's guideline only skips nodes flagged disabled, so `expectTextContrast` drops failures whose node carries the tile's disabled reason as its hint.
3. **Nodes touching the screen edge or a scrollable's edge.** The suite skips these because they may be partly scrolled away. Flutter's `MinimumTapTargetGuideline` does the same.

## 4. Defects → FIX tickets

These are reported to the owning tickets and were not fixed here, because QA-08 owns only `test/a11y/` and this document. Each entry is in `knownA11yDefects`, `knownErrorDefects` or `knownTimelineDefects` in `a11y_support.dart`. Remove an entry from that register when its FIX ticket lands, and the suite then enforces the fix.

| FIX ticket | Owner file | Severity | Defect | Suggested fix |
|---|---|---|---|---|
| FIX-UX-22-2 | `lib/src/editor/preview/manipulation_overlay.dart` (UX-22) | **Blocker** (crash) | Selecting an audio clip throws `ArgumentError: property "transform.scale" does not apply to this item: MediaClip` in `ManipulationOverlay.build`. The semantics label calls `_transformOf` for every non-cue selection, including clips with no visual props. In release the overlay becomes an error box while an audio clip is selected. | Compute the transform only for items that `PropertyKeys.scale.appliesToItem` accepts, and give audio selections no overlay label or actions. |
| FIX-UX-12-1 | `lib/src/editor/timeline/timeline_semantics.dart` (UX-12) | Major | With ripple on, which is the default (`ViewState.rippleEnabled = true`), the clip actions "Move 1 frame/second earlier/later" are no-ops. `MoveItems(ripple: true)` by less than the item's length returns unchanged, so screen-reader users always hear "Not changed". | Nudge with `ripple: false` (a nudge is not a reorder), or in ripple mode move past the neighbour. |
| FIX-UX-12-2 | `lib/src/editor/timeline/timeline_semantics.dart` (UX-12) | Major | Marker, transition and keyframe nodes have only tap (select or open). ARCH §17.9 and ux.md §19.1 ask for custom actions such as delete and jump. | Add custom actions: delete marker and jump to it; remove transition and open settings; delete keyframe and jump to it. |
| FIX-UX-22-1 | `lib/src/editor/preview/manipulation_overlay.dart` (UX-22) | Minor | With nothing selected, the preview overlay is a tap/long-press semantics node with no label. Screen readers say "button". | Label it ("Preview, tap to select an item") or exclude the recognizers from semantics while nothing is selected. |
| FIX-UX-14-1 | `lib/src/editor/transport/transport_bar.dart`, `timecode_text.dart` (UX-14) | Minor | The time readout button ("Playhead position", which opens the go-to-time prompt) is 35–41 px tall. Its label is read twice, once from the pressable and once from `TimecodeText`'s `Semantics`. | Give the pressable at least 44 px of height. Drop the inner label, or exclude it under the button. |
| FIX-UX-14-2 | `lib/src/editor/transport/transport_bar.dart` (UX-14) | Minor | Transport buttons are 44×40 when the bar is 40 px tall: compact landscape (844×390) and 568×320 at 1.35. Affected buttons: frame step, edit-point jumps, add marker, snapping, ripple, zoom. | Make the bar's touch height 44 or more, or extend each button's hit area vertically. |
| FIX-UX-11-1 | `lib/src/editor/timeline/track_headers.dart` (UX-11) | Minor | Track header buttons on 32 px text and subtitle lanes (name/menu, lock, show/hide) are 32 px tall. ARCH §17.2 allows those lanes at 32 px, so a lead decision is needed: either a lane height of 44 or more on touch, or header hit areas that extend past the lane. | Extend the hit areas, or raise the touch minimum for text and subtitle lanes. |
| FIX-UX-16-1 | `lib/src/editor/inspector/inspector_rows.dart` (UX-16) | Minor | Slider-row value chips (tap to type a value) have `minHeight: 32` and read the value twice ("Volume, 100%" plus "100%"). The slider underneath is a full-size adjustable alternative. | Use `minHeight: 44` (or a hit-test padding) and `excludeSemantics` on the inner text. |
| FIX-KIT-1 | `packages/danaview_ui_kit/lib/src/components/danaview_chips.dart` (existing app kit, lead) | Minor | `DanaviewSegmentedControl` segments are 38 px tall inside the 44 px control (3 px inset) and read their label twice. Seen in Speed (Constant/Curve) and Format (Colour/Blur). | Let each segment's pressable fill the full control height. Exclude the label text from semantics under the pressable. |

**Blocker assessment.** FIX-UX-22-2 is a functional blocker for every user, not only screen-reader users, and must land before release. The other defects do not block the a11y checklist.

### 4.1 Observations (no FIX ticket)

- Flow sheets and dialogs (`showDanaviewSheet` and `showDanaviewDialog` in the app kit) still slide or fade in with reduce motion on. ux.md asks for instant *panel* transitions, and the inspector dock complies. The platforms themselves keep a reduced transition for modal sheets.
- Disabled tool tiles do not expose a disabled state to screen readers. They stay tappable by design and announce the reason as a hint.
- The playhead slider steps one frame per increase or decrease (ARCH §17.9, UX-12). ux.md §19.1's "±1 s, plus ±1 frame custom actions" is superseded by ARCH.

## 5. Manual screen-reader script

Run this once on one iOS device with VoiceOver and once on one Android device with TalkBack. Use the real app with `--dart-define=DANAVIEW_EDITOR=true --dart-define=DANAVIEW_AUTO_CAPTIONS=true` and a project made from `frame_counter_1080p30.mp4` plus one music file. Record pass or fail and notes per step. "Blocker" means a task cannot be completed without sight.

| # | Step | Expected |
|---|---|---|
| 1 | Home → swipe to "Open video editor" → double-tap | Projects opens. Focus lands on the title, and "New project" is reachable. |
| 2 | New project → pick media → create | The import sheet reads each file and its progress. The editor opens and the save status is read in the title button. |
| 3 | Swipe through the top bar, preview, transport and timeline | Every control has a name. The order is top bar → preview → transport → timeline → tool strip. Nothing is read as an unlabeled "button". |
| 4 | Focus the playhead → swipe up or down (VO) / volume keys or swipe (TalkBack) | Moves one frame per step and reads the timecode. While playing, it updates at most once per second. |
| 5 | Focus a clip → open the actions rotor (VO) / actions menu (TalkBack) | Lists split, delete, move ±1 frame/second and trim ±1 frame/second. Running "Move 1 second later" moves the clip and announces "Moved to …" (with ripple off; see FIX-UX-12-1). |
| 6 | Run "Split at playhead", then Undo from the top bar | "Split" is announced and undo restores the clip. Announcements do not pile up when actions run fast. |
| 7 | Focus a marker, a transition and a keyframe (select a keyframed clip) | Each is read with its time. Double-tap selects the marker, opens the Transition panel, or selects the keyframe. |
| 8 | Select a text item → focus the preview | "Selected text, scale … percent, rotation … degrees". The move, scale and rotate actions change it with one undo entry each. |
| 9 | Open Adjust → change Exposure with the slider, then type a value | The slider is adjustable and reads percentages. The value chip opens a field (see FIX-UX-16-1). |
| 10 | Track header → toggle lock, visibility and mute | Each is read as a button with its state. The new state is announced. |
| 11 | Export → choose a preset → start → wait | Progress is readable. Completion is announced, and Save and Share are reachable. |
| 12 | Auto captions → consent → run on a 10 s clip | The consent text is readable and the progress announced. Captions appear in the Captions panel's cue list. |
| 13 | Relink (rename a source file first) | The missing-media banner is read. The relink sheet lists files with actions. |
| 14 | Turn on Reduce Motion (iOS) / Remove animations (Android) → open and close the inspector, record a voiceover | The dock does not animate. The voiceover countdown digits do not animate. |
| 15 | Set the device language to Arabic (RTL) → open the editor | The chrome mirrors (close button on the right, headers on the right). The timeline still runs left to right, and timecodes read correctly. |
| 16 | Largest accessibility text size (the app clamps to 1.35×) | Nothing is cut off or overlapping, and every control is still reachable. |
| 17 | Select an audio clip | The preview stays intact and the clip's actions are reachable. This fails until FIX-UX-22-2 lands. |

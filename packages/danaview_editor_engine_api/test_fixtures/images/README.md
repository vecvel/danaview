# Reference-renderer goldens

Reference PNGs of the Dart CPU reference renderer (`lib/src/reference/reference_renderer.dart`,
ARCH §11.6) for ~30 plans at a few output frames each, plus everything an engine needs to render
the same frames: the plans and the decoded source content. Used by IOS-11 / AND-10 (render parity
on the simulator and emulator, including the 8× scale-keyframed text case) and QA-03 (device parity).

Generated by `dart run tool/regen_goldens.dart` (from `packages/danaview_editor_engine_api`); never edit
by hand. Regeneration needs review: a golden changes only when the render math or a plan changes.

## Layout

| Path | Content |
|---|---|
| `goldens.json` | manifest (below) |
| `plans/<name>.json` | the golden plans: byte copies of the CORE-29 contract corpus (`origin` names the source file) and API-03's own plans (canonical RenderPlan v1, one line) |
| `goldens/<name>_f<kkkk>.png` | 8-bit RGB golden of output frame `k` |
| `sources/<key>_f<jjjjj>.png` | synthetic video frame `j` (RGB, display-oriented) |
| `sources/<key>.png` | synthetic image (RGB, display-oriented) |
| `sources/sprite_<sw>x<sh>.png` | synthetic sprite colour (RGBA, **straight** alpha in the PNG; premultiply on load — the content is white, 50 % black or transparent, so the conversion is exact) |
| `sources/sprite_<sw>x<sh>_glyphs.png` | 16-bit grey, big-endian: glyph order per pixel (65535 = background), only for sprites with `reveal: true` |
| `sources/lut_<n>.vlut` | `.vlut` v1 table (ARCH §10.2) |

## goldens.json

```
{schema, generatedBy, spec, rule, tolerance {meanAbs, p99, ssim, edgePixelsExcluded},
 renderer {maxSupersample, videoLongSide, imageLongSide},
 goldens: [{name, plan, origin, longSide, size: [w, h], renderScale,
            frames: [{k, tUs, png, layers: [ids drawn]}],
            sources: {assetId: {kind: "video", fps, size, frames: {"<j>": png}}
                              | {kind: "image", size, png}
                              | {kind: "sprite", size, png, glyphs | null}
                              | {kind: "lut", n, vlut}}}]}
```

- Output frame `k` is evaluated at plan time `tUs = timeOfFrame(k)` of `canvas.fps` (D-35).
- `size` is `round(canvas·renderScale)`, `renderScale = longSide / max(canvas.w, canvas.h)`; engines
  render the plan at that size (preview render size or a scaled export) and compare.
- Video assets: the displayed frame is the one with the greatest PTS ≤ s + 500 µs on a constant-rate
  source at `fps` (frame `j` at `j·10⁶/fps`), `s` from the layer's `map` (ARCH §11.5). `frames` lists
  exactly the frames these goldens use; feed them to the engine (e.g. as a test decoder or images at
  those PTS). Source pictures are small (long side 128) and are scaled to `base` like any source.
- Audio assets have no files here; mixes are in `../vectors/audio_mix.json`.

## Reference renderer rules beyond ARCH §11.6

- Layers draw bottom → top in (z, t0, id) order onto the opaque `bg` (its alpha is ignored).
- Each layer is rasterized in base-local orientation at `round(base·|s|·renderScale)` px: sources
  are box-filtered by footprint supersampling (≤ 8 × 8 bilinear taps per texel); effects run on that
  raster (blur σ in raster px = `blur·0.03·min(W, H)·renderScale`); placement samples it bilinearly at
  each output pixel centre mapped through `M⁻¹`. Edges are not anti-aliased; parity excludes edge
  pixels.
- A missing `base` is the canvas size (solids, images, media) or `sw/sscale × sh/sscale` (sprites).

## Synthetic content

`SyntheticSources` (`lib/src/reference/synthetic_sources.dart`) derives everything from the asset's
`uri` and display size: video frames carry a colour ramp, a red orientation square (top left), a
key-green `#00B140` and a key-blue `#0000FF` disc, a bar sweeping once per second and a 12-bit
frame-index barcode (LSB left) along the bottom; images are a two-colour checkerboard with a ring;
sprites are box-letter glyphs with a drop shadow. The nominal video rate comes from a `<n>p<fps>` /
`<n>k<fps>` token in the file name (else 30 fps).
